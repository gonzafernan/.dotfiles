# Code style

- Comments: only where the code is genuinely hard to understand (a hidden constraint, a non-obvious workaround, a surprising invariant). Keep them brief — one or two lines, not multi-paragraph explanations. Don't explain what the code does or reference the task/fix that introduced it.

# Commits

- Single-line commit message only, as brief as possible. No body, no trailers (no Co-Authored-By).
- Follow Conventional Commits: `type(optional-scope): lowercase imperative summary` (feat, fix, refactor, docs, chore, ...).
